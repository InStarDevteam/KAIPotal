# 쉽게 이해하는 국방지능형플랫폼포털

> 사용자 관점에서 포털의 역할, 기능 흐름, 플랫폼 관계를 쉬운 말로 정리합니다.

## 1. 이 포털은 무엇인가

국방지능형플랫폼포털은 데이터 플랫폼, AI 플랫폼, 지능형 클라우드/CMP를 **하나의 창구에서 연결해주는 통합 진입점**입니다.

쉬운 비유를 들자면,

- **포털** = 종합 안내소 + 신청 창구 + 승인 창구 + 현황판
- **데이터 플랫폼** = 데이터를 모으고 정리하고 가공하는 창고와 공장
- **AI 플랫폼** = 모델을 만들고 학습·평가·배포하는 연구실과 운영센터
- **지능형 클라우드/CMP** = GPU·서버·스토리지 같은 자원을 빌려주는 자원센터

포털은 이 세 공간을 사용자가 한 번에 찾아보고, 필요한 업무를 신청하고, 진행 상황을 확인할 수 있게 연결합니다.

## 2. 왜 필요한가

데이터 플랫폼, AI 플랫폼, 클라우드는 각자 별도의 시스템입니다. 사용자가 이곳저곳 로그인하고, 다른 메뉴를 찾아다니고, 승인 절차를 따로 진행해야 한다면 업무 효율이 떨어집니다.

포털은 이런 문제를 해결합니다.

- **하나의 계정과 화면**으로 접근
- **통합검색**으로 데이터·모델·도구를 한 번에 찾기
- **프로젝트 중심**으로 업무를 묶어서 관리
- **승인·감사 흐름**을 한눈에 보기
- **사용량·크레딧·쿼터**를 투명하게 조회

## 3. 누가 사용하는가

| 사용자 | 주요 업무 |
|--------|-----------|
| 일반 사용자 | 데이터·도구 탐색, 업무 신청 |
| 데이터 엔지니어 | 데이터셋 등록·정제, 메타데이터 관리 |
| 데이터 사이언티스트 | 데이터 분석, AI 모델 개발 지원 |
| AI 개발자 | AI 작업환경 사용, 모델 학습·배포 |
| 프로젝트 관리자 | 프로젝트·멤버·자원·크레딧 관리 |
| 군별 관리자 | 육해공군 테넌트·쿼터·사용량 통제 |
| 보안 관리자 | 반입·반출 승인, K-RMF 증빙, 감사 |
| 사업관리자 | 요구사항 대응현황, API 연계현황 추적 |

## 4. 사용자는 어떤 순서로 쓰는가

일반 사용자의 전형적인 흐름은 다음과 같습니다.

1. 포털에 접속한다.
2. 접근코드 또는 Google 계정으로 로그인한다.
3. 통합 대시보드에서 전체 현황을 확인한다.
4. 통합검색이나 서비스·도구 카탈로그에서 필요한 것을 찾는다.
5. 프로젝트/워크스페이스에서 업무 단위를 만든다.
6. 반입·반출 승인, 크레딧 관리 등 필요한 업무를 신청한다.
7. 마이페이지에서 내 이력과 설정을 확인한다.

관리자는 추가로 다음을 수행합니다.

- 사용자 등록·승인·권한 관리
- 반입·반출 승인 처리
- K-RMF 증빙 자료 관리
- 요구사항 대응현황 및 API 연계현황 조회

## 5. 데이터 플랫폼과 무슨 관계인가

데이터 플랫폼은 실제 데이터를 다룹니다. 데이터 수집, 저장, 가공, 분석, 카탈로그화를 담당합니다.

포털은 다음 역할을 합니다.

- 데이터셋·도구 검색
- 데이터 반입·반출 신청
- 프로젝트와 데이터 플랫폼 작업환경 연결
- 사용량과 상태 조회

데이터 처리 자체는 데이터 플랫폼에서 수행되며, 포털은 사용자가 데이터 플랫폼을 이용하기 위한 창구 역할을 합니다.

## 6. AI 플랫폼과 무슨 관계인가

AI 플랫폼은 모델 개발·학습·평가·배포를 담당합니다.

포털은 다음 역할을 합니다.

- AI 작업환경과 도구 신청
- 프로젝트와 AI 플랫폼 연결
- 학습·평가 이력 조회
- 모델 성과물 반출 승인 관리

모델 학습과 배포 자체는 AI 플랫폼에서 수행되며, 포털은 신청·조회·승인 흐름을 관리합니다.

## 7. 클라우드/CMP와 무슨 관계인가

지능형 클라우드/CMP는 GPU·서버·스토리지 같은 자원을 제공하고, 쿼터와 과금을 관리합니다.

포털은 다음 역할을 합니다.

- 프로젝트·워크스페이스 생성 신청
- 크레딧 할당 및 사용량 모니터링
- 군별 쿼터·사용량 조회
- 자원 부족 시 추가 신청

실제 자원 생성과 과금은 클라우드/CMP에서 수행되며, 포털은 사용자의 신청과 현황 조회를 지원합니다.

## 8. 관리자 메뉴는 왜 있는가

관리자 메뉴는 포털이 단순한 조회 도구가 아니라 **운영·통제·감사를 위한 업무 시스템**임을 보여줍니다.

- **관리자 콘솔**: 사용자·권한·정책·메뉴 관리
- **반입·반출 승인**: 보안 검토와 승인 workflow
- **K-RMF 증빙관리**: 보안 평가 자료 관리
- **육해공군 관리**: 군별 테넌트와 쿼터 통제
- **요구사항 대응현황**: RFP 요구사항 추적
- **플랫폼 API 연계현황**: 플랫폼 간 연계 후보 관리
- **업무흐름/연계 시나리오**: 사용자 여정과 연계 흐름 시각화

## 9. 요구사항 대응현황은 왜 필요한가

RFP에는 21개 SFR과 163개 기능목록이 있습니다. 요구사항 대응현황은 이 많은 항목이 포털의 어떤 메뉴·화면에서 어떻게 대응되는지를 한눈에 보여줍니다.

이는 다음에 도움이 됩니다.

- 제안 발표 시 구현 범위 설명
- 사업 착수 후 개발 우선순위 결정
- 진척도 추적 및 보고
- 누락 항목 사전 발견

## 10. 플랫폼 API 연계현황은 왜 필요한가

포털은 단독으로 모든 기능을 수행하지 않습니다. 데이터·AI·클리우드·인증·보안 플랫폼과 연계해야 합니다.

API 연계현황은 다음을 정리합니다.

- 어떤 메뉴가 어떤 플랫폼과 연계되는가
- 어떤 API·이벤트·파일 연계가 필요한가
- 어떤 연계는 현재 설계안 단계인가
- 어떤 연계는 후속 개발 대상인가

이를 통해 사업 착수 후 인터페이스 정의서 작성과 개발 범위를 명확히 할 수 있습니다.

## 11. 업무흐름/연계 시나리오는 왜 필요한가

시나리오는 **사용자 관점에서 플랫폼을 어떻게 사용하는지**를 보여줍니다.

예를 들어,

- 데이터 사이언티스트는 데이터를 어떻게 찾고, 어떤 승인을 거쳐, 어떤 플랫폼에서 분석하는가
- AI 개발자는 프로젝트를 어떻게 만들고, 자원을 어떻게 신청하며, 어떻게 모델을 배포하는가

이러한 흐름을 시각화하면 복잡한 시스템도 이해하기 쉬워집니다.

## 12. 제안 발표에서 어떻게 설명하면 되는가

제안 발표에서는 다음 흐름으로 설명하면 됩니다.

1. **포털은 통합 진입점이다** — 세 플랫폼을 연결하는 안내소·신청 창구
2. **누가 어떻게 쓰는가** — 사용자 유형별 메뉴와 흐름
3. **RFP와 어떻게 매핑되는가** — SFR별 대응 화면
4. **실제 업무는 어떻게 흘러가는가** — 4개 대표 시나리오
5. **포털과 플랫폼의 경계는 어디인가** — 포털이 하지 않는 일과 플랫폼이 하는 일
6. **현재 어디까지 되었는가** — 화면 구현 수준과 후속 연동 범위

이 순서를 따륾면 청중이 포털의 위치와 가치를 자연스럽게 이해할 수 있습니다.
