# 리스크 및 대응방안

> 국방지능형플랫폼포털 실 구축 시 고려해야 할 주요 리스크와 대응방안입니다.

| No | 리스크 | 영향도 | 발생 가능성 | 대응방안 | 비고 |
|---:|---|---|---|---|---|
| 1 | Keycloak 권한 모델과 포털 권한 모델 불일치 | 높음 | 중간 | 역할/그룹 매핑 테이블을 별도로 설계하고, Keycloak group/role을 포털 권한으로 정규화하는 어댑터를 구현 | 초기 설계 단계에서 권한 매트릭스 확정 |
| 2 | OpenMetadata/OpenSearch 동기화 지연 | 중간 | 중간 | 비동기 이벤트 기반 동기화 및 주기적 재동기화 배치 운영, 동기화 상태 모니터링 추가 | 대용량 데이터는 점진적 색인 |
| 3 | 보안등급 기반 접근제어 누락 | 높음 | 낮음 | 검색 API 및 데이터 상세 API에서 사용자 역할/그룹/보안등급을 실시간 평가하도록 Backstage Permission Policy 및 백엔드 인가 로직 적용 | 보안 테스트 시 우선 검증 |
| 4 | Kubernetes/OpenStack/CMP 연동 난이도 | 높음 | 높음 | 각 시스템별 인터페이스 사전 조사, mock adapter를 먼저 구현하고 단계별 실 연동, 연동 실패 시 fallback 정책 수립 | 3차 구축에서 집중 |
| 5 | 반입·반출 보안검토 workflow 복잡도 | 중간 | 중간 | 승인 단계를 단계별 상태 머신으로 모델링하고, 파일 저장소/DLP/마스킹 검토는 별도 마이크로서비스로 분리 | 보안 담당자와 협의 |
| 6 | 크레딧 차감 기준 불명확 | 중간 | 중간 | GPU/CPU/스토리지/네트워크 단위 환산 기준을 사전 정의하고, 관리자가 조정 가능한 정책 파라미터로 분리 | 환경설정 메뉴에서 관리 |
| 7 | 군별 멀티테넌트 경계 정책 복잡도 | 높음 | 중간 | 테넌트별 Keycloak realm/group, K8s namespace, OpenStack project를 매핑하고, 정책 위임 체계를 문서화 | 테넌트 설계를 1차 구축에서 확정 |
| 8 | 감사로그 저장/보관/검색 성능 | 중간 | 중간 | 감사로그를 별도 저장소에 적재하고, OpenSearch로 색인하여 빠른 검색 지원, 보관 주기 및 아카이빙 정책 수립 | 감사로그 설계를 초기에 포함 |
| 9 | RFP 요구사항 변경 | 높음 | 중간 | 변경 관리 프로세스를 사전 정의하고, 요구사항 추적표를 지속적으로 갱신, 영향 범위 분석 후 협의 | CHANGE_LOG 관리 |
| 10 | 일정/인력/테스트 범위 리스크 | 중간 | 높음 | WBS 및 마일스톤을 단계별로 관리, 주요 기능부터 우선 구현, 통합 테스트 일정을 충분히 확보 | 10% 예비 공수 확보 |

## 추가 고려사항

- **보안 인증**: ISMS-P, CC, 국정원 보안 기준 등 필요한 인증 범위를 사전에 확정
- **외부 시스템 의존성**: Keycloak/OpenSearch/OpenMetadata 버전 업그레이드 시 영향도 분석
- **데이터 마이그레이션**: 기존 데이터의 보안등급 재분류 및 메타데이터 매핑 계획 수립
- **사용자 수용성**: 연구자 중심의 UX 검증 및 피드백 반영 체계 운영
