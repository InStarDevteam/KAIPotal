# 포털과 플랫폼 역할/경계 정리

> 보안등급: 낮음(낮)

## 목적

국방지능형플랫폼포털(이하 "포털")과 데이터/AI/클리우드 플랫폼 간의 책임 경계를 명확히 하여, PoC 이후 실제 연계 개발 및 운영 시 혼선을 줄입니다.

## 포털의 역할

포털은 **단일 접점 + 권한 통제 + 업무 workflow 오케스트레이션** 계층입니다.

| 역할 | 설명 |
|------|------|
| 단일 접점 | 국방지능형플랫폼의 메인 포털(SFR-001) |
| 통합 인증 | Keycloak/Firebase 기반 SSO, 게스트/관리자 구분(SFR-003/005/019) |
| 메뉴/권한 관리 | RBAC, 메뉴/프로그램, 육해공군 테넌트 단위 접근 통제(SFR-005/006/021) |
| 업무 신청/승인 | 프로젝트 생성, 반입·반출, 서비스 신청 workflow(SFR-009~012/016) |
| 현황 조회 | 대시보드, 검색, 카탈로그, 사용량, 크레딧 조회(SFR-014/015/017) |
| K-RMF/감사 | 증빙 자료 연계, 감사 로그 수집(SFR-002/004/020) |

## 플랫폼의 역할

| 플랫폼 | 주요 책임 | 포털이 요청하는 대표 기능 |
|--------|-----------|---------------------------|
| **데이터 플랫폼** | 데이터 수집/저장/가공/분석, 데이터 카탈로그, OpenSearch | 데이터 작업환경 조회, 데이터셋/모델 검색, 데이터 반출 파일 전송 |
| **AI 플랫폼** | 모델 개발/학습/배포, AI 작업환경, 모델 레지스트리 | AI 작업환경 조회, AI 모델 조회, AI 성과 반출 파일 전송 |
| **지능형 클라우드/CMP** | 인프라/컴퓨팅/스토리지 자원, 과금/크레딧, 쿼터 | 프로젝트/워크스페이스 생성, 크레딧/자원 사용량 조회 |
| **인증/권한** | 사용자/조직/역할/테넌트 관리, SSO, 세션 | 로그인/SSO, RBAC 권한 조회, 테넌트/쿼터 조회 |
| **보안/K-RMF** | 반입·반출 승인, 증빙 관리, 감사 로그, DLP | 반입·반출 workflow, K-RMF 증빙 동기화, 감사 로그 수집 |
| **지능형 서비스** | 이미지/음성/자연어 등 AI 응용 서비스 | 대시보드/검색 결과에 활용 가능(향후 연계) |

## 경계 원칙

1. **대체 금지**: 포털은 플랫폼의 핵심 기능(데이터 분석, 모델 학습, 인프라 관리)을 직접 구현하지 않습니다.
2. **집계/조회 위주**: 포털은 플랫폼으로부터 현황/메타데이터를 조회하여 보여줍니다.
3. **신청/승인 오케스트레이션**: 업무 workflow의 시작/승인/이력은 포털에서, 실제 자원 생성/파일 처리는 플랫폼에서 수행합니다.
4. **권한 위임 최소화**: 포털이 플랫폼 관리자 권한을 가지지 않도록 하며, 사용자 토큰/위임 토큰 기반으로 연계합니다.
5. **보안/감사 통합**: 모든 연계 호출은 포털 감사 로그에 남기며, 민감 연계는 K-RMF 보안 검토를 거칩니다.

## 연계 방식

| 방식 | 적용 예시 |
|------|-----------|
| REST API | 인증, 권한, 작업환경 조회, 프로젝트 생성, 검색 |
| 이벤트(Kafka/SSE) | 감사 로그, 공지/알림 |
| 파일(S3/SFTP) | K-RMF 증빙, 반출 파일 전송 |
| gRPC(후보) | AI/데이터 플랫폼 고성능 연계 |

## PoC 한계

현재 `플랫폼 API 연계현황`은 실제 API 연동이 아닌 **설계안/후보 목록**입니다. 실제 연동은 각 플랫폼 API 명세 확정 후 개발되어야 합니다.
