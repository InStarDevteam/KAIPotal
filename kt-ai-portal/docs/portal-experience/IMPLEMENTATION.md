# 포털 로그인·메인 경험 개선 — 2026-09-24

이번 작업은 기존 RFP·제안서의 포털/플랫폼 책임 경계와 앞선 군별 설정·감사 기능을 보존하면서 진입 경험과 운영·개발 관리 기능을 개선했다. 외부 플랫폼 본체를 포털 안에 재구현하지 않았다. 작업 전 존재하던 미커밋 변경은 유지했다.

## 바로 확인하기

현재 로컬 미리보기: http://localhost:3000 — 접근코드 `demo1234`.

재실행:

```sh
cd backstage-portal
node .yarn/releases/yarn-4.13.0.cjs workspace app build --config ../../app-config.yaml --config ../../app-config.design-review.yaml
cd ..
node scripts/serve-design-review.mjs
```

이 프로필은 명시적인 고객 협의용 환경이다. 실제 플랫폼 토큰이나 기관 인증을 사용하지 않는다. 로컬 서버는 127.0.0.1에만 바인딩한다. 운영 배포는 수행하지 않았다.

관리 화면을 비교하려면 오른쪽 내 계정 → 역할 미리보기에서 포털 관리자를 선택한다. 이 역할은 테넌트 관리 화면에서 슈퍼유저로 표시된다. 운영 환경은 브라우저의 역할 선택이나 접근코드로 권한을 부여하지 않는다.

로그인에 시안별 입장 버튼 4개를 제공하고 선택한 시안을 세션 동안 유지한다. 메인 하단에도 협의용 전환기를 두었다. `app.designReviewEnabled: false`로 선택기를 제거하면 기본 Aurora 화면이 적용된다. 최종 고객안 확정 후 기본 시안을 변경하고 협의 설정을 해제하면 된다. 운영 설정에서 `previewAuthEnabled`와 `proposalCapture.enabled`를 동시에 켜지 않는다.

## 사용자 동선과 기능 보존

- 첫 화면은 사이드바·상세 통계·공지 테이블 없이 AI, 데이터, 클라우드, VDI에 집중한다.
- 상단 ‘모든 앱’은 Google식 아이콘 팝업이다. 네 플랫폼과 현재 권한으로 사용 가능한 내부 메뉴를 제공한다.
- ‘포털 업무’는 검색·카탈로그·프로젝트/워크스페이스·신청/승인·크레딧·게시판·내 계정·관리 화면의 진입점이다. 기존 경로와 권한을 유지했다.
- 상세 업무 화면에서는 메뉴 버튼으로 사이드바를 열 수 있다. 홈으로 돌아오면 다시 감춘다.
- 미연결 플랫폼은 성공으로 가장하지 않고 연결 주소 미등록 안내를 표시한다. 관리자가 HTTPS 접속 주소를 등록하면 서버 권한 재검증 후 해당 서비스로 이동한다.
- 계정 메뉴에서 프로필, 테넌트 설정, 도움말, 로그아웃을 제공한다. 테넌트별 로고·색상·포털명·사용자 정의 환영 문구가 반영된다.
- 화면의 RFP 요구사항 식별자와 대응표 문구를 제거했다. 원본 요구사항 문서·내부 추적 매핑은 보존했다. 이전에 비활성화한 K-RMF 전용/요구사항 대응/발표 시나리오 화면은 그대로 보관한다.

## 테넌트·권한

`/tenant-settings`에서 브랜딩과 메뉴 설정에 더해 플랫폼 주소·사용 여부·순서·역할 허용 범위를 관리한다. `/tenant-management`에서는 소속 사용자별 플랫폼 접근권한과 테넌트 관리자 지정을 관리한다. 해병대 테넌트를 예시 데이터에 추가했다.

플랫폼 이용 여부는 테넌트 활성화 AND 역할 허용 AND 사용자별 허용을 함께 적용한다. 서버가 실제 이동 직전에 다시 검사한다. 개인 즐겨찾기·순서는 테넌트와 사용자별로 분리한다. 개인 순서가 없으면 테넌트 기본 순서를 따른다.

슈퍼유저는 관리 대상 테넌트의 유효한 소속을 가진 상태에서 다른 사용자를 테넌트 관리자로 지정할 수 있다. 기존 서버 역할 부여·회수 API와 감사 원장을 재사용한다. 테넌트 관리자는 다른 테넌트 설정과 슈퍼유저 역할을 부여할 수 없다. 역할 미리보기는 명시적인 데모 프로필 전용이다.

운영 데이터는 PostgreSQL RLS·버전 충돌 검사·감사 트랜잭션을 이용한다. 데모는 브라우저 저장소를 사용하며 동일 수준의 운영 보안을 주장하지 않는다. 이전 설정에 새 메뉴가 추가되어도 브랜딩과 기존 메뉴 순서를 보존하도록 보완했다. 편집 중 테넌트 변경·브라우저 이탈 보호를 유지했다.

신규 마이그레이션: `backstage-portal/packages/backend/migrations/portal/20260924000001_platform_access.js`. 이전 테넌트 설정 마이그레이션과 함께 운영 반영이 필요하다. 이번 작업은 운영 DB를 변경하지 않았다.

## 개발 관리자와 샘플 업무

`/developer-console` 및 기존 별칭 `/platform-api-integration`에서 기존 API 후보 38개와 VDI 후보 2개를 검토한다. API 목록·검색·플랫폼별 관계·요청/응답 초안·담당자 협의 항목·JSON 명세 내려받기를 제공한다.

샘플 계약 검증은 실제 실행되며 정상·필드 누락·인증 만료·시간 초과 분기를 확인한다. 실제 진단은 서버 등록 HTTPS 목적지와 허용된 GET 경로만 사용한다. 8초 제한, 64KB 응답 제한, 리다이렉트 차단, 테넌트 바인딩, 응답값 비식별화와 서버 감사 기록을 적용했다. 실제 플랫폼 주소·토큰이 없으므로 실플랫폼 성공을 주장하지 않는다. [상세 연동 설정](DEVELOPER_CONSOLE.md)을 참고한다.

제안 게시판은 등록 입력값을 보존하고 내 제안 수정/삭제·공감·관심·댓글·검토 결과를 저장한다. 작업환경 신청은 7단계 입력 전체·자원·기간 검증과 승인/반려 결과를 저장한다. 두 기능의 데모 저장은 테넌트+사용자별로 격리한다. 실제 플랫폼 자원을 생성하지 않으며 운영 미연결 모드에서 제출을 성공한 것처럼 처리하지 않는다.

## 운영 전환의 남은 일

로그인 화면은 기관 OIDC 인증과 서버 신원·소속·권한 경로를 이용하도록 구성했다. 화면 자체로 MFA·단말 보안 검증을 완료했다고 표시하지 않는다. IdP의 MFA, 단말 상태, 접속망 정책, 실제 플랫폼 SSO 위임과 연속 신뢰 판단은 기관 시스템 연동·실증이 필요하다.

다른 기존 업무 화면에는 여전히 예시/메모리 데이터가 남는다. 사용자 프로필·세션·크레딧·카탈로그·프로젝트 전체 생애주기 등은 실제 API와 영속 데이터로 전환해야 한다. 실제 기관 인증, 실플랫폼 API 및 운영 배포는 이번 로컬 검증 범위 밖이다.
