# 외부 연계 확인 및 이번 추가 구현

확인일: 2026-10-01. 고객 시연 개선 배포 작업 중 코드·설정 키·Cloud Run 환경변수 이름을 확인했다. 비밀 값은 문서에 기록하지 않았다. 이 문서는 기능 구현과 외부 시스템 연결 완료를 구분한다.

## 이번 작업에서 외부 의존 없이 완료한 항목

환경설정의 변경 이력은 기존 `portal.fc_portal_setting_history` 원장을 이용해 실제 조회 화면으로 연결했다. `GET /v1/portal-settings/history`는 현재 소속의 `settings.manage` 권한을 검사하고, 트랜잭션 안에서 테넌트 문맥과 FORCE RLS를 적용한다. 변경자 이름·실제 저장 시각·분류·설정 키·전후 값을 표시하며 분류 필터와 페이지 탐색을 제공한다. 추가 migration은 필요 없다.

민감 설정은 종전 UI 마스킹만으로는 응답 본문에 값이 남을 수 있어, 현재 값과 변경 이력 모두 서버 응답에서 제거하도록 보완했다. 일반 JSON 설정 안의 `apiKey`, `token`, `password` 등 중첩 키도 확인한다. 민감 설정은 전체 값을 숨겨 마스킹된 내용을 다시 저장하는 문제를 방지한다. 일반 문자열 `true`, `123`이 불리언·숫자로 잘못 해석되던 문제도 수정했다.

검증 명령과 결과:

- `node scripts/test-portal-settings-history.mjs`: 임시 PostgreSQL과 실제 BFF 7개 시나리오 통과. 변경 이력 원자성, 버전 충돌 시 이력 미생성, 일반 사용자 거부, 교차 테넌트 차단, 민감값 비노출, 분류·페이지 범위, 문자열 보존 확인.
- 환경설정 프런트 단위 테스트 18개 통과. 실제 응답 표시·다음 페이지·민감값 보호·권한 거부·실패 후 재시도·잘못된 응답 처리 포함.
- 설정 서비스 단위 테스트 23개 통과.
- `yarn tsc --noEmit` 통과. app/backend lint 오류 0개(기존 경고 24/5개). 세부 실행 로그는 `evidence/settings-history-*-tests.txt`에 보존했다.

후속 전체 회귀 검사에서는 프런트 255개·백엔드 167개, 합계 **422개 단위 테스트**가 통과했다. 위 설정 관련 테스트는 이 전체 결과의 부분집합이며 별도로 더해 계산하지 않는다. 결과는 `deployment/app-tests.txt`, `deployment/backend-tests.txt`에 있다.

## 실제 운영 DB를 사용하는 후보 검증

사용자의 후속 구현·배포 승인 후 후보 백엔드에서 인증된 BFF 조회 17개 경로, 부분 실패 없는 업무 집계, 교차 테넌트 거부, 국방형 프로필 저장 후 원본 복구를 확인했다. 운영 DB에 일반 프로젝트 `[시연] 군수 데이터 분석` 1개와 작업환경 요청 1개를 등록하고 승인까지 검증했다. 이는 합성 시연 데이터이며, 외부 플랫폼 자원을 생성하지 않았다. 검증 증적은 [후보 API 결과](deployment/candidate-api/backend-verification.json)를 따른다. 최종 사용자 URL 배포·트래픽 승격 상태는 [DEPLOYMENT_REPORT.md](DEPLOYMENT_REPORT.md)에서 별도로 확인한다.

## 외부 서비스 연결 상태와 필요한 계약

| 항목 | 확인한 실제 상태 | 완료에 필요한 외부 정보 |
|---|---|---|
| 기관 인증·세션 | 배포 환경은 Backstage Guest 인증이며 포털 등록 신원·소속·역할은 서버 DB에서 검사한다. OIDC 모듈은 소스에 있지만 실제 issuer/realm 설정·세션 관리 어댑터가 없다. 기존 Keycloak 기록은 localhost PoC다. | 기관 IdP URL/realm/client/redirect 등록, 인증서·서비스 자격증명, 사용자 subject 매핑, 현재 세션 식별 클레임, 본인 세션 조회·회수 API, refresh 및 기존 access token 무효화 정책, 재인증·MFA 정책 |
| 플랫폼 작업환경 | 신청·승인·감사 원장은 실제 DB에 저장된다. 승인은 자원 생성 완료를 뜻하지 않으며 플랫폼 생성 API나 작업 조회 어댑터가 없다. | AI/CMP 작업환경 생성·상태조회·삭제 명세, 플랫폼별 테넌트/프로젝트/사용자 연결 키, 인증·네트워크, 멱등성 키·작업 ID·재시도/대사 계약 |
| CMP 자원·계량 | 연결된 자원 풀·GPU 할당 및 계량 원천이 없다. 연동 대기 상태를 표시하며 수치를 생성하지 않는다. | 자원 풀·할당·이용량 API, 단위/수집주기/시간대, 프로젝트 연결 키, 크레딧 단가·반올림·정산 정책, 결측/중복/지연 처리 기준 |
| 이메일·비밀번호·개인 API 키·알림 | 해당 포털 화면은 연동 준비 상태로 보존되어 있다. 포털 프로필 저장은 인증 계정 자체의 변경 권한을 부여하지 않는다. | 담당 IdP/계정 서비스 확정, 이메일 검증·비밀번호 변경 정책, 키 발급/회수 범위와 저장 방식, 알림 전달 수단/발신정책/수신동의 계약 |
| 개발 관리자 API 테스트 | 34개 API 협의 항목과 서버 진단 기능이 있다. 실제 GET 접속은 등록된 HTTPS 목적지·허용 경로로만 실행하며 응답 값은 비식별화한다. | 각 담당사의 확정 OpenAPI/JSON Schema, 테넌트별 `PORTAL_INTEGRATION_TARGETS`, 서버 토큰/망 접근 설정, 정상·오류 응답 및 접속 테스트 대상 |

Cloud Run 환경변수 이름 확인 결과 `PORTAL_INTEGRATION_TARGETS`, `PORTAL_CONNECTOR_*_TOKEN`, 기관 OIDC/CMP 설정은 등록되어 있지 않다. 확인된 주요 키는 앱·백엔드 URL, 접근코드, Backstage 세션 secret, Firebase 설정, 데모 허용 목록, 포털 DB 연결 정보다. 플랫폼 이동 URL은 테넌트별 접근 설정에 저장할 수 있지만, 이동 링크 등록은 API 연동이나 SSO 완료와 별개다.

설정 이름뿐 아니라 실제 인증된 `/v1/integrations/targets` 응답도 확인했다. `ai`, `data`, `cloud`, `vdi`, `identity`, `security`, `portal`, `external`의 **8개 대상 모두 `configured=false`**다. 따라서 개발 관리자 테스트 화면 구현을 외부 시스템 접속 성공으로 보고하지 않는다.

외부 계약이 없는 상태에서 세션 회수·플랫폼 자원 생성·실사용량 수집을 임의 프로토콜이나 샘플 응답으로 완료 처리하지 않았다. 기관 및 플랫폼 담당사 정보가 제공되면 기존 서버 인가·테넌트 격리·감사 체계 안에서 어댑터를 구현하고 실제 시스템까지 검증해야 한다. 포털의 접근코드는 고객 협의용 입장 절차이며, 실제 제로트러스트 인증 검증 완료를 뜻하지 않는다.
