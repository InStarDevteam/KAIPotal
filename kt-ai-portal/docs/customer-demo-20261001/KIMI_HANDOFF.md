## 1. 운영 반영

이번 개발에서는 운영 배포를 하지 않았다. 운영 반영 작업이 승인된 작업 문맥에서만 다음 순서로 진행하고 실제 결과를 기록하라.

1. 현재 revision/트래픽과 DB migration 이력·백업 상태를 확인한다. 작업 트리를 reset/revert하지 않는다.
2. 기존 보안 연결 절차와 migration 전용 계정 `portal_migrator`로 `node scripts/run-portal-migrations.mjs` 실행. 환경변수는 `POSTGRES_HOST/PORT/USER/PASSWORD/DB`. 비밀번호를 로그·문서·명령 출력에 남기지 않는다.
3. 이번 신규 migration은 다음 2개다.
   - `20261001000001_repair_work_runtime_grants.js`: 이동한 업무 원장 4개에 `portal_runtime` 최소 ACL 복구. RLS를 비활성화하지 않는다.
   - `20261001000010_user_profile.js`: 국방형 사용자 프로필 원장 및 runtime 권한.
4. 실제 runtime 계정으로 `node scripts/check-portal-work-runtime.mjs`를 실행한다. exit 0과 필요한 ACL/FORCE RLS를 확인한다. health 200만으로 집계 성공 판정 금지.
5. 실제 배포 설정으로 프런트와 백엔드를 다시 빌드한다. `python3 scripts/build-firebase-staging.py`는 `app-config.demo.yaml` 이후 `app-config.customer-showcase.yaml`을 병합하도록 수정되었다. 디자인 4종은 켜고 `proposalCapture.enabled`는 false로 유지한다.
6. 로컬 브라우저 테스트용 `app-config.customer-review.yaml` 및 localhost용 `packages/app/dist`를 운영에 그대로 배포하지 않는다. 위 운영 빌드 결과를 사용한다. `scripts/lib/customer-review-server.mjs`는 테스트 인증을 사용하는 폐기형 로컬 검증 도구다. 배포 서버로 사용 금지.
7. 기존 Cloud Build/Cloud Run/Firebase 절차로 배포한다. minInstance=1과 즉시 복귀 가능한 이전 revision을 유지한다. 무조건적인 schema rollback은 하지 않는다.
8. 로그인 후 디자인 4종, 소속 콤보, `/portal-work`, 국방 프로필 조회/저장, 내 프로젝트, 작업환경 신청/승인, 주요 화면을 재검증한다. 운영 쓰기 검증은 지정된 테스트 계정과 테스트 프로젝트에 한정하고 생성 항목을 기록한다.

## 2. 고객 시연 데이터

새 테이블이 비었다는 이유로 성공 이력·사용량·실세션을 임의 표시하지 않는다. 승인된 시연 테넌트에 일반 프로젝트를 만들고 멤버를 등록한 뒤 기존 신청/승인 흐름을 사용한다. 군번은 실개인정보 대신 명확한 합성 테스트 값을 쓴다. AI/데이터/클라우드/VDI 접근 권한과 연결 주소는 기존 관리 화면에서 등록한다.

현재 운영 협의 계정은 국방부 공통 1개 멤버십이다. 콤보가 열리더라도 다른 군이 보이지 않는 것은 권한 제한이다. 고객이 승인한 사용자-테넌트-역할 매핑으로만 추가한다. 프런트 localStorage나 역할 미리보기로 운영 권한을 우회하지 않는다.

## 3. 후속 개발 우선순위

| 우선 | 범위 | 완료 기준 |
|---|---|---|
| P1 | 기관 IdP 세션 | 본인 세션 조회, 현재 세션 식별, 다른 세션 폐기, 재인증, 실제 토큰 무효화, 감사 기록. 샘플 목록/클라이언트 삭제만으로 완료 처리하지 않음 |
| P1 | 플랫폼 작업환경 연계 | 승인 후 플랫폼 작업 ID, 생성 중/실패/준비 완료, 멱등성·재시도, 원장-플랫폼 상태 대사. 승인을 생성 완료와 구분 |
| P1 | CMP 자원·계량 | 테넌트/프로젝트/워크스페이스 연결 키, 수집 시각, 단위·누락 상태, GPU/CPU/메모리·크레딧 사용량 계약 확정 |
| P2 | 인증·계정 하위 기능 | 이메일 인증·비밀번호 변경·외부 사용자 등록 승인·개인 API 키·알림의 실제 담당 서비스와 계약 확정 |
| P2 | 설정 이력 | 저장된 설정 변경의 실제 서버 이력 조회, 변경자·시간·대상 표시. 브라우저 샘플 이력 사용 금지 |
| P2 | 개발 관리자 계약 | 보존된 34개 카탈로그 항목의 소유 플랫폼·URL·인증·요청/응답·오류·접속 테스트를 담당사와 확인. 추정 실증 전용 API 재추가 금지 |

새 기능을 RFP로 임의 확장하지 마라. 기능 경계 변경이 필요하면 근거와 영향을 먼저 제시한다. 메뉴를 없애서 미연동 문제를 숨기거나, mock 응답을 실응답으로 보고하지 마라.

## 4. 회귀 검증 및 보고

`VALIDATION.md`의 명령을 실행한다. 특히 실제 PostgreSQL로 업무 집계 권한 장애/복구, FORCE RLS, 교차 테넌트 차단, 마지막 관리자 보호, 프로필 본인 접근·버전 충돌을 검증한다. 브라우저 테스트는 데스크톱과 390px 모바일, 4개 디자인, 6개 사용자층, 실제 신청-승인 흐름을 확인한다.
