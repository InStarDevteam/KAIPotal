## UI 사용성

- 제목·본문·보조정보 크기와 대비를 구분하고, 날짜/자원/크레딧은 카드의 독립된 줄에 배치했다.
- 기존 표가 필요한 이력은 최소 너비와 가로 스크롤을 보장해 한 글자 줄바꿈을 막았다.
- 새 입력 필드는 고유 `id`와 연결된 label을 제공한다. 메뉴 버튼은 키보드로 이동할 수 있다.
- 프로젝트 링크는 실제 상세 선택 쿼리로 이동한다. 예시 도메인·HTTP·인증정보가 포함된 워크스페이스 주소는 접속 링크를 만들지 않는다.
- 사용자/소속 전환 시 마이페이지 내용을 새로 구성하여 이전 계정의 입력·목록이 남지 않게 했다.

## 배포 전 필수 연결

신규 migration `20261001000010_user_profile.js`는 `portal.fc_user_profiles`만 생성하며 기존 사용자·권한을 변경하지 않는다. `portal` 스키마 명시, 강제 RLS, tenant 격리 정책, 복합 PK(tenant,user)를 적용한다. 표준 `portal_runtime` 역할이 있으면 SELECT/INSERT/UPDATE를 부여한다. 별도 이름의 런타임 역할을 사용하는 환경은 같은 권한을 지정해야 한다.

`createMyProfileRouter` 등록과 migration을 포함한 백엔드 배포 후 프런트엔드를 배포해야 한다. 새 API가 배포되지 않은 경우 실패 메시지와 비활성 저장 버튼을 표시하며 예시 프로필로 대체하지 않는다.

기관 SSO 세션 관리, 이메일·비밀번호 정책, 플랫폼 사용량, 알림 전달, 개인 API 인증 연계는 아직 연결 대상이다. 현재 시연에서 이 항목을 실제 실행 완료로 설명하면 안 된다.
