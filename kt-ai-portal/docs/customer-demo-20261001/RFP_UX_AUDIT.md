# 고객 시연용 RFP·UI/UX 전수 점검 — 2026-10-01

## 적용 기준

현재 App.tsx에 등록된 18개 화면 경로(17개 기능 화면 + 개발 관리자 별칭 1개)와 하위 패널, portal BFF 라우트를 점검했다. 초기 소스 검토 이후 사용자가 후속 구현과 배포를 승인했으며, 실제 운영 DB를 사용하는 후보 백엔드의 인증·조회·프로필 저장·프로젝트 신청/승인도 검증했다. 최종 트래픽 승격과 배포 결과는 [DEPLOYMENT_REPORT.md](DEPLOYMENT_REPORT.md)를 따른다. **서버 연결**은 포털 BFF와 원장 연결을 뜻하며, 외부 AI·데이터·CMP 엔진이나 고객 인증 시스템까지 연결 완료라는 뜻은 아니다.

근거는 `FINAL_RFP_PORTAL_BOUNDARY_REVIEW.md`의 SFR-001~021 경계, `production-upgrade/REQUIREMENT_IMPLEMENTATION_MATRIX.csv`, `final-completion/IMPLEMENTATION_REPORT.md`, 현재 프로젝트·요청·K-RMF 원장 및 2026-10-01 고객 정정이다. 최신 고객 확인을 과거 설계 문서의 추론보다 우선한다. 화면에는 요구사항 ID를 표시하지 않는다.

**실증은 체계를 활용하는 활동이다.** 기존 `FINAL_RFP_PILOT_PROJECT_MAPPING.md`는 실증 수행 요구를 별도 실증 관리 프로그램과 API로 확장 해석한 기록이다. 현재 기획 기준에서 폐기하며 원문에는 정정 안내를 달았다. 별도 실증 탭·연계 배지는 제거하고 일반 프로젝트의 등록·멤버·환경 신청·승인·성과 반출을 그대로 사용한다. 기존 파일은 기록과 영향 분석을 위해 보존한다. 최근 반영된 K-RMF 현황/증적/조치 기능은 별개의 최신 구현 기준이므로 유지한다.

## 하위 패널의 미연결 경계

기능을 삭제하거나 동작 완료로 표시하지 않는다. 실제 처리가 불가능한 항목은 원래 메뉴 위치에서 짧은 설명과 연결 상태를 보여 준다. 샘플 체험 모드에는 기존 예시가 남지만 운영 원장 모드에서 운영 수치로 보이지 않게 한다.

- 관리자: 사용자 등록 승인, 외부 사용자 상세 관리, 로그인 정책, 비밀번호 정책, 플랫폼 운영도구 주소는 인증·계정·각 플랫폼의 연결이 필요하다. 사용자 목록·권한 부여/회수·메뉴 설정·감사 경로는 유지한다.
- 테넌트: 리소스 풀, 쿼터 관리, 사용량 대시보드, 프로젝트 사용량, 경계 정책 원장, 쿼터 변경 이력은 원천 연결이 필요하다. 테넌트 개요는 접근 가능한 실제 멤버십으로 표시하고, 위임 관리는 기존 실제 관리자 지정 화면을 재사용한다.
- 환경설정: 초기 점검 때 미연결이던 변경 이력은 이번 후속 구현에서 실제 원장 API와 화면으로 연결했다. 설정 관리 권한·현재 테넌트·RLS를 검사하고 민감 값은 서버에서 숨긴다. 설정 저장과 변경 이력 조회가 IdP/CMP 정책의 실제 적용까지 뜻하지는 않는다.
- 마이페이지: 외부 인증 제공자의 다른 기기 세션·강제 종료, 이메일 인증, 비밀번호 변경, 알림 전송·개인 API 키 발급·실자원 계량은 별도 연결 확인이 필요하다. 새 국방형 프로필 및 내 서버 원장 조회와 구분한다.
- 플랫폼: 신청·승인 성공이 실제 컨테이너·GPU·VDI 준비 완료라는 의미가 되지 않도록 안내한다. 접속 URL과 연결 상태는 각 플랫폼의 응답으로 결정한다.

## 컴팩트한 UX 적용

1. 일반 프로젝트는 **목록 / 작업환경 신청** 2개 탭으로 정리했다. 생성과 멤버 관리 기능은 유지한다. 과제 실증은 이 흐름의 이용목적에 포함된다.
2. 서버 작업환경 신청은 프로젝트·자원·기간을 우선 배치하고 데이터/모델/도구/보관 정책은 펼쳐 볼 수 있게 했다. 승인 대기와 내 신청 내역은 같은 화면 하단에서 확인한다. 반려에는 검토 의견이 필요하다.
3. 표 머리글은 줄을 나누지 않고, 한글 단어·날짜·자원 값이 세로로 잘리지 않도록 자연스러운 너비와 컨테이너 가로 스크롤을 적용했다. 본문 14px, 행간 1.6, 명확한 머리글 배경과 선택 행, 키보드 초점 표시를 공통 적용했다.
4. 프로젝트 목록은 검색과 키보드 버튼을 지원한다. URL의 프로젝트 선택을 보존하고, 다른 프로젝트로 전환할 때 이전 상세·종료 확인 상태를 지운다. 상세 재시도 오류는 잡아서 화면에 안내한다.
5. 빈 원장 / 조회 실패 / 연결 준비 중 / 예시 데이터는 서로 다른 상태다. 빈 데이터베이스라는 이유로 성공 이력이나 자원 수치를 생성하지 않는다.

## 검증과 후속 기준

- 프로젝트/작업환경 영역 4개 테스트 스위트, 14개 테스트 통과. 활성 참여 프로젝트 제한, 다른 프로젝트 배제, 자원/기간 오류, 선택 구성 보존, 승인과 실제 생성의 상태 차이를 확인했다.
- RBAC 중복 회수 라우트가 안전한 후속 핸들러를 가리고 있던 결함을 수정했다. 동시성 잠금·현재 권한 재검증·마지막 관리자 보호가 적용되는 단일 핸들러를 유지하고 회수 사유를 보존한다. 실제 일회성 PostgreSQL DB 검사 52개가 통과했으며, 일반 역할 회수·다른 관리자 회수·마지막 관리자 보호·미래 활성화 관리자 제외를 포함한다. 결과: `evidence/portal-runtime-rbac-tests.txt`.
- 전체 타입 검사와 통합 브라우저·PostgreSQL 테스트는 주 개발 작업의 `evidence` 실행 기록으로 집계한다. 소스 정적 목록에 존재한다는 사실만으로 전 기능 실동작을 통과 처리하지 않는다.
- 초기 로컬 점검 단계에서는 고객 운영 DB에 시연 데이터를 넣지 않았다. 이후 사용자의 후속 구현·배포 지시에 따라 실제 운영 DB에 일반 프로젝트 **`[시연] 군수 데이터 분석` 1개와 작업환경 요청 1개**를 등록하고 승인까지 확인했다. 합성 예시임을 설명에 표시했으며 별도 실증 관리 기능이나 외부 플랫폼 자원은 생성하지 않았다. 생성 ID와 검증 결과는 [후보 API 검증 기록](deployment/candidate-api/backend-verification.json)에 보존했다.
- 전체 단위 테스트는 프런트 255개·백엔드 167개, 합계 **422개 통과**했다. 설정 이력의 실제 PostgreSQL 7개 시나리오는 권한·테넌트 차단, 버전 충돌 시 이력 미생성, 서버 민감값 비노출을 포함한다.
- 후속 외부 연동은 인증 세션 API, 사용자 등록 승인, 플랫폼 자원 수집/쿼터, 외부 검색 원천이 남아 있다. 설정 이력은 이번 구현 범위에서 완료했다. 실제 연계 대상 8종은 모두 `configured=false`이며, 원천/책임/실패 상태와 필요한 계약은 [INTEGRATION_STATUS.md](INTEGRATION_STATUS.md)에 정리했다.

자동 추출한 전체 BFF 메서드·경로·소스 위치는 [BACKEND_ROUTE_INVENTORY.csv](BACKEND_ROUTE_INVENTORY.csv)에 있다. 이는 소스 등록 목록이며 실제 배포의 인증 성공이나 외부 플랫폼 연결 시험 결과를 대신하지 않는다.
