# TER-008 실증 프로젝트 포털 매핑

> **2026-10-01 정정 · 현재 구현 기준으로 사용하지 않습니다.** 고객 확인에 따라 실증은 구축된 체계를 사용하는 사업 활동이며, 별도 실증 프로젝트 등록·KPI·합성데이터·시뮬레이터 하위 시스템을 포털 요구기능으로 간주하지 않습니다. 아래 내용은 과거 해석 기록으로 보존합니다. 일반 프로젝트·작업환경 신청·반출 기능은 유지합니다. 최신 기준: [고객 시연 RFP·UX 점검](customer-demo-20261001/RFP_UX_AUDIT.md).


> 최종공고문 260723_v1의 TER-008(실증 프로젝트) 요구사항을 포털 구조와 매핑합니다.  
> 포털은 실증 모델의 개발/학습/평가를 직접 수행하지 않으며, 과제 현황·워크스페이스·반출·산출물 관리를 지원합니다.

## 1. TER-008 실증 프로젝트 요구사항

| 요구 ID | 요구사항 명칭 | 요구 내용 | 포털 담당 범위 |
|---------|---------------|-----------|----------------|
| TER-008 | 실증 프로젝트 관리 | 육군종합정비창 3개 과제를 대상으로 실증 프로젝트를 등록·관리하고, 결과에 따라 최대 4개 소요부대로 확대 | 과제 등록/현황/워크스페이스/반출/산출물 관리 |

- **실증 대상**: 육군종합정비창 내 3개 AI/데이터 분석 과제
- **실증 목적**: 국방지능형플랫폼의 AI/데이터 기능을 실제 업무에 적용하여 성과와 안정성을 검증
- **성과물**: 실증 모델, 분석 보고서, 데이터셋, 반출 산출물, 평가 보고서
- **확대 조건**: 3개 과제 실증 결과가 기준을 충족하면 최대 4개 소요부대로 확대 적용

## 2. 육군종합정비창 3개 과제 예시

| 과제 번호 | 과제명(예시) | AI/데이터 플랫폼 활용 | 포털 반영 항목 |
|-----------|--------------|----------------------|----------------|
| TER-008-01 | 부품 수요 예측 | 데이터 분석/예측 모델 | 데이터 작업환경 요청, 데이터 반출 승인 |
| TER-008-02 | 정비 이력 기반 고장 예측 | AI 모델 학습/추론 | AI 작업환경 요청, 모델 반출 승인 |
| TER-008-03 | 이미지 기반 불량 진단 | 이미지 분석/AI 모델 | AI 도구 선택, 반출 승인, 실증 결과 등록 |

> 실제 과제명은 사업관리자/요구부대와 협의하여 확정합니다. 위 표는 포털 매핑을 위한 예시입니다.

## 3. 최대 4개 소요부대 확대 조건

- **기준 1차 실증**: 육군종합정비창 내 3개 과제로 1차 실증 수행.
- **확대 조건**: 1차 실증 결과(성능, 안정성, 보안, 운영 적합성)가 평가 기준을 충족.
- **확대 범위**: 최대 4개 소요부대(육군종합정비창 외 추가 부대)로 적용.
- **포털 반영**: 프로젝트/워크스페이스에 `소요부대` 필드를 다중 선택/추가할 수 있도록 구조를 확장.
- **워크스페이스 분리**: 확대 시 부대별 워크스페이스 또는 하위 프로젝트를 분리하여 관리.

## 4. 포털 반영 화면 (project-workspace)

### 4.1 프로젝트 목록/상세

- **실증 프로젝트 여부** 표시: 일반 프로젝트와 실증 과제를 구분하는 뱃지/필터 추가.
- **소요부대** 필드: 등록/상세에서 1개 → 최대 4개 부대 선택/표시.
- **과제 번호/명** 필드: TER-008-01, TER-008-02, TER-008-03 형태로 관리.
- **상태**: 계획 → 진행 중 → 1차 실증 완료 → 확대 적용 → 종료.

### 4.2 워크스페이스 요청/관리

- **AI/데이터 작업환경 선택**: SFR-007/008에 따라 데이터셋·모델·CPU/GPU·라이브러리/도구 선택.
- **워크스페이스 접속 링크**: AI/데이터 플랫폼에서 제공한 접속 URL을 프로젝트 상세에 노출.
- **종료/반출 workflow**: 실증 종료 시 산출물 저장/반출을 반입·반출 승인과 연계.
- **추가 자원 요청**: 실증 중 추가 GPU/스토리지/크레딧 요청을 크레딧 관리와 연계.

### 4.3 반출/성과 관리

- 실증 모델, 분석 보고서, 데이터셋 등의 반출은 `반입·반출 승인` 메뉴에서 처리.
- 반출 시 보안등급/승인권자 확인 → 승인/반려 → 감사 로그 및 K-RMF 증빙 자료로 연계.

### 4.4 플랫폼 API 연계현황

- TER-008 관련 연계 후보를 추가:
  - 실증 과제 상태 조회 (포털 → AI/데이터 플랫폼)
  - 실증 워크스페이스 생성/종료 (포털 → 클라우드/CMP)
  - 실증 결과 파일 반출 (포털 → AI/데이터 플랫폼, 보안/K-RMF)
  - 소요부대 확대 정보 동기화 (포털 → 인증/권한)

## 5. API/데이터/AI 플랫폼 전제조건

| 플랫폼 | 전제조건 | 포털 연계 시 필요 정보 |
|--------|----------|------------------------|
| AI 플랫폼 | 실증 과제별 AI 작업환경 생성/조회 API, 모델 학습/추론 상태 API, 접속 URL 발급 | 과제 ID, 워크스페이스 ID, 모델 ID, 상태, 접속 링크 |
| 데이터 플랫폼 | 데이터셋/파이프라인 조회 API, 데이터 작업환경 생성/조회 API, 반출 파일 전송 인터페이스 | 데이터셋 ID, 작업환경 ID, 반출 파일 경로, 메타데이터 |
| 클라우드/CMP | 프로젝트/워크스페이스 생성 API, 쿼터/크레딧 조회 API, 자원 사용량 수집 | 프로젝트 ID, 워크스페이스 ID, 쿼터, 사용량, 크레딧 잔액 |
| 보안/K-RMF | 반출 승인 workflow API, 감사 로그 수집, 증빙 자료 저장 | 반출 요청 ID, 승인 상태, 감사 이력, 증빙 파일 |
| 인증/권한 | 사용자/부대/조직 정보, 테넌트/쿼터 조회 API | 소요부대 코드, 사용자 역할, 테넌트 정보 |

## 6. 후속 일정

1. 실증 과제 확정 및 과제 번호/명 부여
2. AI/데이터/클라우드 플랫폼의 실증 전용 API 명세 확정
3. 포털 `project-workspace`에 실증 과제/소요부대 필드 추가(소스코드 변경)
4. 반입·반출 승인 workflow에 실증 산출물 유형 추가
5. 1차 실증 → 평가 → 최대 4개 소요부대 확대 적용
