# 권한별 포털 업무 첫 화면

2026-09-24. 메인과 상단의 **포털 업무** 링크는 `/portal-work`로 직접 이동합니다. 앱 모양 아이콘의 ‘모든 앱’ 팝업은 유지합니다. 권한은 기존 정책을 그대로 사용하며, 이 화면은 기존 업무를 모아 보여주는 진입 화면입니다.

| 사용자층 / 기존 역할 | 첫 화면 우선 내용 | 주요 실행 | 이어지는 기존 화면 | 범위 및 제한 |
|---|---|---|---|---|
| 일반 사용자 / `general-user` | 내 프로젝트, 내 신청 현황, 잔여 크레딧, 이용 가능 플랫폼 | 프로젝트 이어가기, 작업환경 신청, 자산 검색 | 프로젝트/워크스페이스, 통합검색, 카탈로그, 크레딧, 반입·반출, 마이페이지, 제안 게시판 | 신청 내역은 현재 테넌트·계정 저장 범위. 승인 권한 추가 없음 |
| 프로젝트 관리자 / `project-manager` | 담당 프로젝트, 신청·검토 대상, 프로젝트 자원·크레딧 | 작업환경 신청·검토 화면으로 이동 | 프로젝트/워크스페이스, 크레딧, 반입·반출 등 기존 허용 메뉴 | `project.approve` / `workspace.approve` 기존 권한 사용. 화면 진입을 완료 승인으로 표시하지 않음 |
| 군별 관리자 / `branch-admin` | 소속 서버·자원 현황, 크레딧 요청, 플랫폼 접근 현황 | 사용자·접근 관리, 자원 풀, 테넌트 설정 | 테넌트 관리, 관리자 콘솔, 크레딧, 감사, 군별 포털 설정 등 | 자기 테넌트 범위. 기존 정책에 없는 프로젝트·반출 승인 권한을 부여하지 않음 |
| 슈퍼유저 / `portal-admin` | 선택 테넌트의 자원 현황, 권한에 맞는 검토 대상, 운영 메뉴 | 테넌트 전환, 테넌트·관리자 관리, 플랫폼 연계 콘솔 | 테넌트 관리, 관리자 콘솔, 개발 관리자, 환경설정 등 전체 허용 메뉴 | 기존 명칭 ‘포털 관리자’ 유지. 전 군 합계를 임의로 만들지 않고 선택 테넌트 기준 표시 |
| 보안 관리자 / `security-manager` | 반입·반출 검토 목록 우선, 최근 접속·활동, 확인이 필요한 기록 | 개별 요청 검토, 감사 이력 조회 | 반입·반출 승인, 접속·사용 이력, 조회 가능한 연계 콘솔 등 | `export.review` / `audit.view` 기존 권한 사용. 브라우저 활동을 기관 인증 로그로 표시하지 않음 |
| 보안 감사자 / `security-auditor` | 최근 접속·활동 기록, 감사 이력 진입 | 읽기 전용 감사 조회 | 접속·사용 이력, 통합검색·카탈로그, 조회 가능한 연계 콘솔 등 | 승인·설정 변경 기능을 추가하지 않으며 신청 목록을 승인 업무처럼 노출하지 않음 |

## 분기 및 권한

- 역할 이름 대신 **현재 유효 권한 집합**으로 분기합니다. 복수 역할 우선순위는 포털 운영 → 테넌트 운영 → 보안 검토 → 프로젝트 운영 → 감사 조회 → 개인 업무입니다.
- 각 링크는 기존 메뉴의 요구 권한과 테넌트별 메뉴 표시 설정을 다시 확인합니다. 하단 ‘모든 포털 업무’에는 현재 허용된 기존 기능을 유지합니다.
- 공통 진입점인 포털 홈·포털 업무·테넌트 설정은 숨김 불가 메뉴입니다. 테넌트 설정 자체의 관리 권한은 그대로 적용됩니다.
- 테넌트·계정 변경 시 첫 화면의 검색·필터·저장 상태를 초기화합니다. 반입·반출 페이지의 계정 변경 시 기존 로컬 상태가 남던 부분도 같은 기준으로 초기화했습니다.

## 데이터의 현재 수준

- 고객 협의용 데모에서 기존 프로젝트·자원·크레딧 샘플을 재사용합니다. 프로젝트 샘플은 명시된 소속 매핑으로 제한하며, 실제 개인 프로젝트 소속을 서버에서 확인한 데이터는 아닙니다.
- 작업환경·반입반출 신청 및 승인 결과는 기존 브라우저 저장소와 연결합니다. ‘새로고침’은 이 저장 내역을 다시 읽습니다.
- 사용자 간 공유 승인함이나 실시간 자원 수집은 이번 화면 개편에서 새로 구현하지 않았습니다. 다른 사용자의 저장소를 임의로 합치지 않습니다.
- 실서비스 모드에서는 데모 수치 대신 연동 대기와 `—`를 표시합니다. 실제 집계 API, 프로젝트 멤버십, 테넌트 관리자 승인함 연동이 필요합니다.
- 기관의 IdP/MFA/단말 신뢰 검증과 서비스별 SSO는 별도 연동 대상입니다. 디자인의 로그인 화면을 제로트러스트 검증 완료로 간주하지 않습니다.
