# 군별 포털 설정 및 감사 이력 정비

2026-09-18 요청 반영. 검토 근거: 저장소의 FINAL_RFP_PORTAL_BOUNDARY_REVIEW, TENANT_MANAGEMENT_DESIGN, RBAC_MENU_MANAGEMENT_DESIGN, SECURITY_POLICY_AUDIT_DESIGN 및 운영 전환 검토 자료. 원본 RFP PDF는 현재 작업 자료에 없으므로 전체 요구사항 적합 판정을 의미하지 않는다.

## 화면 변경

- K-RMF 전용 메뉴, 화면 진입, 대시보드 위젯, 보안 과제 및 예시 업무 연결은 주석 처리하여 비활성화했다. 원본 컴포넌트와 내부 추적 자료는 보존한다.
- 사용자 화면에서 요구사항 ID, 대응 현황 탭 및 요구사항 툴팁을 제거했다. 요구사항 진도/대응, 발표용 업무 시나리오와 API 연계 설계 현황 경로는 비활성화했다.
- `군별 포털 설정`(`/tenant-settings`): 대표/강조 색상, 로고 주소, 포털 이름, 약칭, 환영/도움말 문구, 메뉴 표시·명칭·그룹 내 순서. 저장 후 상단·메뉴·공통 테마·홈 안내에 적용된다.
- 메뉴의 표시 여부는 권한을 추가하지 않는다. 숨김 메뉴는 직접 경로 접근도 차단하며, 홈과 설정 메뉴는 복구를 위해 유지한다.
- `접속·사용 이력`(`/audit-history`): 선택 군의 활동 통합 조회, 기간·사용자·구분·결과·검색 필터, 통계, 상세, CSV. 포털 관리자는 접근 권한이 있는 군을 선택할 수 있고, 군 관리자는 서버에서 확인한 자기 군 범위를 이용한다.
- 기존 관리자 콘솔의 메뉴/감사 탭은 새 관리 화면으로 연결한다.
- 통합검색 자동완성·필터에도 결과 접근권한을 적용해 비공개 자산의 메타데이터 노출을 줄였다.

## 저장 및 권한

- 운영 모드는 `/api/portal/v1/me`의 검증된 소속·권한으로 메뉴와 작업을 판단한다. 브라우저의 역할 미리보기, Firebase 이메일 목록으로 운영 권한을 올리지 않는다.
- 외관 변경은 `settings.manage` 또는 `tenant.manage`, 메뉴 변경은 `menu.manage`, 감사 조회는 `audit.view`가 필요하다. 서버에서 다시 검사한다.
- 설정 저장은 PostgreSQL 테넌트 RLS, 변경 버전 비교, 트랜잭션 내 감사 기록을 사용한다. 감사 기록 실패 시 업무 변경도 롤백한다.
- 로고는 HTTPS 또는 내부 경로를 허용한다. 스크립트 URL, 외부 프로토콜 상대 경로, 유효하지 않은 메뉴, 저대비 대표 색상 등은 거부한다.
- 명시적 데모 설정에서는 군별 브라우저 저장소를 사용한다. 같은 군의 다른 역할도 같은 외관·메뉴를 보며, 수정 권한은 별도 검사한다. 다른 군 설정은 분리된다. 데모 기록은 서버 감사 원장으로 취급하지 않는다.

## 감사 범위

서버 권한 검사, 소속 선택, 역할 부여/회수, 군별 포털 설정 변경, 이력 조회/내보내기를 원장에 기록한다. 화면 이용과 포털 접속 신호도 수집하되 사용자 화면 활동으로 구분한다. 클라이언트는 사용자 식별자·처리 결과·서버 시각을 지정할 수 없다. 숨김 또는 권한 없는 화면의 사용 기록은 허용하지 않는다.

CSV는 현재 필터와 조회 시점을 기준으로 서버가 최대 10,000건을 한 번에 수집한다. 초과하면 기간을 좁히도록 안내하며 부분 파일을 정상 결과로 내려받지 않는다. 스프레드시트 수식 실행을 막도록 셀을 이스케이프한다. 조회 중 소속 전환이나 화면 이탈 시 이전 조회 결과와 다운로드를 폐기한다.

## 운영 반영

신규 마이그레이션: `backstage-portal/packages/backend/migrations/portal/20260918000001_tenant_settings.js`.

기존 설정된 배포 절차에서 DB 마이그레이션과 `scripts/seed-portal-reference.mjs` 기준 권한 갱신 후 백엔드·프런트엔드를 함께 배포해야 한다. 본 작업은 코드 및 로컬 검증이며 공유/운영 DB 변경과 외부 배포는 실행하지 않았다.

## 남은 연계 경계

- 실제 인증 시스템의 로그인 실패·로그아웃·세션 만료 이벤트 수집은 인증 공급자 연계가 필요하다. 브라우저 접속 신호를 인증 성공으로 해석하지 않는다.
- 기존 프로젝트·크레딧·반출 등 일부 업무 화면은 데모 자료를 유지한다. 실제 외부 플랫폼 업무 이벤트의 전수 감사 수집을 완료했다고 표시하지 않는다.
- 감사 보관 기간 집행, 외부 SIEM/중앙 로그 반출, 변조 방지 보관 매체·운영 증적 검증은 운영 환경에서 추가 연계해야 한다. 이번 기능만으로 K-RMF 인증 또는 완전 충족을 주장하지 않는다.
- 군별 설정과 이력 API는 서버 신원 등록 및 유효한 소속·역할 데이터가 있어야 사용할 수 있다. 연결 실패 시 데모 데이터로 자동 대체하지 않는다.
