# 기능 전수 점검 및 샘플 데이터 범위 — 2026-10-04

이 문서는 실제 앱 라우트와 BFF의 조회·등록·수정·승인·권한 경로를 코드로 대조한 결과다. 최종 RFP 전체를 새로 승인·검수한 결과는 아니다. 기준은 [10월 3일 요구사항 검토](../requirements-review-20261003/REQUIREMENTS_GAP_REVIEW.md), 저장된 요구영역과 제안서, 최신 고객 지시다. 배포와 실제 DB 샘플 투입의 최종 결과·건수는 [10월 4일 구현·적재·배포 보고서](../data-readiness-20261004/IMPLEMENTATION_REPORT.md)와 시드 검증 증적을 기준으로 한다.

## 화면·원장·데이터 투입 기준

앱의 공개 라우트를 모두 확인했고, 긴 화면은 실제 서버 모드에서 제공하는 하위 기능까지 구분했다. 별도 실증 프로젝트 프로그램과 보류된 요구사항 현황/업무 시나리오 전용 화면은 다시 노출하지 않는다. 아래의 ‘샘플 가능’은 해당 원장에 합성 데이터를 넣어 등록·조회·승인 등을 시연할 수 있다는 뜻이다. 외부 시스템의 실행 성공이나 기관 인증을 대신하지 않는다. 이 표는 후속 데이터 구성 조건도 포함하며, 모든 행을 이번 운영 DB에 적재했다는 뜻은 아니다. **이번 시드는 기존 신원·멤버십·역할·프로필을 보존하고, 이미 승인된 협의 계정을 업무 원장의 행위자로 사용한다.**

| 목록의 키보드 진입/오래된 상세 | 제안·카탈로그의 행 클릭만으로 상세 선택, 제안 새 상세 조회 중 이전 상세가 잔류 | 제목/항목을 실제 버튼으로 진입 가능하게 하고 제안 상세 변경 시 이전 내용을 지움 |
| K-RMF 프로젝트 선택 식별 | 프로젝트 선택지가 이름 대신 내부 UUID를 표시하고 선택 필드의 접근성 연결이 부족 | 기준선 API에서 같은 테넌트·프로젝트의 이름을 조회해 선택 라벨에 표시. 선택 값과 기존 조회 범위/권한은 유지하고 기준선·프로젝트의 한국어 라벨 연결을 명시 |
| 크레딧 거래 목록의 서버 오류 | 정렬이 적용된 거래 쿼리에서 총건수를 집계하며 정렬을 제거하지 않아 PostgreSQL COUNT 문이 실패. 실제 후보 브라우저에서도 거래 조회 500 재현 | 총건수 조회의 복제 쿼리에서만 정렬을 제거. 거래의 시각·ID 순서와 권한은 유지하며 실제 PostgreSQL 목록·다음 페이지·소속 격리 회귀 검증 |

권한, 공개범위, 승인 상태와 외부 실행 책임은 바꾸지 않았다. 전용 실증 기능을 추가하거나 기존 요구기능을 삭제하지 않았다.

## 데이터 정합성과 시연 기준

1. 이번 적재에서는 기존 신원·역할·멤버십·프로필을 보존하고, 이미 승인된 협의 계정만 실제 행위자로 사용한다. 개인 군번·계급·소속 등 개인정보 샘플을 새로 제조·등록하지 않는다. 업무 샘플의 명칭/설명에서 합성 데이터임을 식별한다. 향후 독립 시연 계정·테넌트가 필요하면 실제 등록·승인·권한 부여 경로를 거쳐 범위를 설정하고, 테넌트/역할별 종단간 허용·거부·회수 시험을 수행한다. 외부 인증과 플랫폼 계정 대응은 미확정으로 보존한다.
2. 단수 프로젝트 원장과 기존 검색/업무용 복수 원장을 동일 ID·멤버십으로 맞춘다. 신청→이력, 카탈로그 신청→작업환경 참조, 프로젝트→멤버/초대, K-RMF 기준선→통제→증적/조치 연결을 지킨다.
3. 크레딧 거래는 부호·멱등 키·합계·잔액 정합성을 검증한다. 실측 없는 사용량을 ‘실시간’으로 전시하지 않는다.
4. 첨부 파일 원장에 물리 파일 없는 가짜 경로를 만들지 않는다. 저장소 미설정과 공식 검사/전송 성공을 샘플로 덮어쓰지 않는다.
5. 날짜·상태·공개범위·권한 조합을 다양하게 만들되 등록 화면에서 실제로 입력할 수 있는 범위 안에서 구성한다. 테스트에서만 사용하는 101개/51개 대량 행은 일회성 로컬 DB에 두고 운영 샘플과 구분한다.
6. 같은 시드를 재실행해도 중복되지 않고 사용자가 수정한 값을 덮어쓰지 않게 한다. 기존 운영·협의 데이터를 삭제하지 않는다. 감사는 실제 BFF 작업의 결과로 생성하고 이전 감사 수정/삭제는 하지 않는다.

## 확인된 회귀 증적

- 신규 UI: 프로젝트 페이지/검색/뒤로/소속 전환, 제안 페이지/본인 필터/정렬/집계, 카탈로그 페이지/승인자 범위/101번째 프로젝트 선택, 작업환경 선택의 본인 멤버십을 확인한다.
- 공통 입력 검증: 장문 줄바꿈/들여쓰기, 금지 제어문자, 길이, 태그·비문자 타입을 확인한다.
- 실제 PostgreSQL `S19-1`: 장문 등록·수정·검토·신청 왕복과 제목 줄바꿈 422를 확인한다.
- 실제 PostgreSQL `S19-2`: 프로젝트 101번째, 다른 테넌트 제외, 문자 `%`의 비확장, 본인 제안 페이지, 실제 본인 공감, 카탈로그 분류/신청 페이지 정합성을 확인한다.
- 실제 PostgreSQL `S7-1`: K-RMF 기준선의 연결 프로젝트 이름 조회와 다른 테넌트의 결과 0건을 확인한다.
- 실제 PostgreSQL `S9-3`: 크레딧 거래 조회 200·실제 총건수, 다음 페이지 빈 결과의 총건수 유지, 다른 테넌트 계정의 거래 404를 확인한다. 총건수 조회에서 정렬된 COUNT 오류가 다시 발생하지 않게 검증한다.
- 10월 4일 해당 도메인 시나리오는 **50/50 통과**했다. 전체 앱/백엔드·배포 후보·공개 사이트 결과는 최종 배포 보고서를 따른다.

## 외부 협의로 남는 동작

데이터를 채워도 기관 인증·세션 회수, 계정 등록/외부 사용자 생애주기, 플랫폼 작업환경 생성·접속·회수, 영구 파일·검사/망간 전달, 실제 자원·쿼터/정산, 외부 검색/카탈로그, 알림/API 키, 공식 K-RMF 인가는 자동으로 완성되지 않는다. 합의해야 할 API·식별자·상태·오류·전달/수신 책임은 [기존 협의 의제 C01~C12](../requirements-review-20261003/REQUIREMENTS_GAP_REVIEW.md)에 유지한다. MDR 사전은 국방 표준원문/등록 규칙을 받을 때 대응·검증할 수 있도록 준비하며, 확정 국방 MDR 준수·승인 완료로 설명하지 않는다.
