# 전체 업무 테이블 샘플 커버리지 — 2026-10-04

운영 Cloud SQL PostgreSQL을 **read-only 트랜잭션**, `portal_migrator` 역할 및 해당 테넌트 context로 조회한 결과다. 조회 시각: **2026-10-04 03:57:10 KST**. DB 전체 `portal` 테이블 57개 중 migration 이력·lock 2개를 제외한 **55개 업무·기술 테이블을 모두 분류**했다. 원장에 샘플을 넣었다고 해당 플랫폼 서비스가 실행됐다는 의미는 아니다.

55개 테이블을 모두 채우기 위해 가짜 계정·권한 위임·기관 인증 세션·실행완료·파일·사용자 행동을 만들지 않았다. 빈 원장은 누락인지, 정상 초기 상태인지, 외부 협의가 필요한지 아래 이유로 구분한다.

사후 검증은 다음과 같다.

- 25개 샘플 테이블 모두 **적재전 + 계획 INSERT = 사후 건수** 일치; 결정적 샘플 74행 모두 존재.
- 신원·소속·그룹소속·역할·프로필·접근정책·설정 등 보호 원장 15개 건수 유지. 기준 자료는 건수만 포함하므로 이 검증을 필드값 snapshot 비교라고 주장하지 않음.
- 기본 dry-run 재검증: 신규 필요 0행, 실제 및 계획의 부모·JSON 참조·사용자 tenant 소속 일치.
- 합성 프로젝트 크레딧: 4거래 합계와 잔액 **108,000 C** 일치. 사용자·테넌트 잔액은 샘플로 만들지 않음.
- FK **68개 모두 VALIDATED**, unvalidated 0개. 단독 ID FK가 보장하지 못하는 tenant 일치는 샘플 전체의 유효 참조 검사로 추가 확인.
- 기술 메타데이터 6개 테이블 건수 일치: 원천 1 / 도메인 22 / 단어 96 / 용어 606 / 코드 161 / 컬럼 548. 기관 사전은 미수령이며 프로젝트 초안만 등록.
- 6개 메타데이터 테이블의 `portal_runtime` 권한은 SELECT 있음, INSERT/UPDATE/DELETE/TRUNCATE 없음.
- 실제 적재에 대한 `system/sample.import` 감사 1행 확인. 사후 검증은 데이터 INSERT/UPDATE/DELETE를 실행하지 않음.

공개 사이트 검증 중 정상 사용자 활동 감사가 추가되면 `fc_audit_events`의 전체 건수는 이 snapshot보다 늘어날 수 있다. 운영 배포·전체 화면 결과는 최종 배포 보고서에서 별도 확인한다.
