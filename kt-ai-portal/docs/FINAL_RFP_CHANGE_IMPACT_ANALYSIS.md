## 5. 실증/K-RMF 영향도

### 5.1 TER-008 실증 프로젝트 영향

- **프로젝트/워크스페이스**: 기존 일반 프로젝트 외에 실증 과제(육군종합정비창 3개 과제)를 구분할 수 있는 필드/카테고리 필요.
- **소요부대 확대**: 1개 → 최대 4개 부대로 확대 시, 워크스페이스 또는 하위 프로젝트 단위가 추가될 수 있음.
- **반출/성과 관리**: 실증 결과(모델, 데이터, 보고서) 반출은 기존 반입·반출 승인 workflow를 통해 처리.
- **AI/데이터 플랫폼**: 실증 모델 학습·추론·평가는 AI/데이터 플랫폼에서 수행, 포털은 현황/산출물 관리.

### 5.2 SER-002~SER-008 K-RMF 영향

- **증빙관리 체계화**: 기존 `K-RMF 증빙관리` 화면의 통제항목·증빙자료·미흡사항 외에 **이행 계획**, **평가/인가 상태**, **운영전환 자료** 영역을 추가.
- **감사 로그 연계**: K-RMF 인가를 위한 사용자/관리자 활동 이력은 관리자 콘솔 감사 로그에서 수집.
- **타 수행사 협업**: SER-006에 따라 타 수행사 제출자료를 통합 조회할 수 있는 별도 보관함/상태 관리 필요.
- **운영전환**: SER-008에 따라 인가 완료 후 인수인계 문서(운영 전환 자료)를 관리할 수 있는 구조 필요.

## 6. 결론

- 최종공고문 260723_v1은 기존 SFR-007/008/015/018/019의 범위를 보강하고, TER-008(실증 프로젝트)와 SER-002~SER-008(K-RMF 인가)을 신규로 추가했습니다.
- 포털은 직접 구현 범위를 넘어서는 데이터/AI 모델 학습, 클라우드 엔진, K-RMF 인가 결정 등은 수행하지 않으며, **신청/승인/조회/증빙 관리** 중심으로 영향을 최소화합니다.
- 후속 단계에서는 각 플랫폼의 실제 API 명세와 K-RMF 평가 기준을 확정하여, 문서에 정리된 매핑을 실제 연동으로 전환해야 합니다.
