# 34단계: 최종공고문 260723_v1 기준 포털 기능 최신화 계획

> 최종공고문 260723_v1이 반영된 요구사항을 기존 포털 구조에 맞춰 기능·화면·문서 측면에서 최신화하는 단계입니다.  
> 본 문서는 소스코드 변경 없이 문서/매핑 정리를 중심으로 기술합니다.

## 1. 34단계 목적

- **최종공고문 260723_v1** 기준으로 변경된 포털 요구사항을 식별하고, 기존 화면/기능에 반영합니다.
- **SFR-007/008/015/018/019**, **TER-008**, **SER-002~SER-008** 변경분을 기존 SFR-001~SFR-021 구조에 맞춰 재매핑합니다.
- 포털이 직접 구현하는 범위와 데이터/AI/클라우드 플랫폼이 제공하는 범위를 명확히 분리합니다.
- 실증 프로젝트(TER-008) 및 K-RMF 인가 대응(SER-002~SER-008)을 포털 화면 관점에서 정리합니다.

## 3. 화면별 수정 내용

### 3.1 요구사항 대응현황 (`/requirement-coverage`, `/requirement-progress`)

- SFR-007/008/015/018/019 및 TER-008, SER-002~SER-008의 기능번호 범위를 추가/보정합니다.
- 최종공고문에서 변경된 항목에 `변경` 태그를 추가하고, 기존 추적표와 비교할 수 있도록 `사전규격 대비 변경` 컬럼을 추가합니다.
- 실증/K-RMF 항목을 별도 필터로 조회할 수 있도록 합니다.
- 포털 직접 구현 범위와 후속 연동 범위를 명확히 구분하여 표기합니다.

### 3.2 통합검색 (`/integrated-search`)

- 검색 필터에 최종공고문 기준 자산 유형(데이터셋, AI 모델, 도구, 문서, 실증과제, K-RMF 증빙)을 반영합니다.
- 보안등급 `공개 / 내부 / 비밀` 기준을 유지하고, 실증/K-RMF 결과에 대한 검색 항목은 별도 라벨로 표시합니다.
- OpenSearch 연결 실패 시 fallback 문구를 중립적으로 유지하며, 신규 유형은 mock fallback 목록에 추가합니다.

### 3.3 프로젝트/워크스페이스 (`/project-workspace`)

- 프로젝트 등록/상세에 **실증 과제 여부** 체크박스와 **소요부대** 다중 선택 필드를 추가합니다.
- 워크스페이스 요청 단계에 AI/데이터 작업환경 선택 항목(SFR-007/008)을 반영합니다.
- 워크스페이스 접속 링크, 종료 시 산출물 저장/반출, 추가 자원 요청 항목을 화면 흐름에 맵핑합니다.
- 최대 4개 소요부대 확대 시 프로젝트 하위 단위(워크스페이스/부대)를 추가할 수 있도록 구조를 확장합니다.

### 3.4 마이페이지 (`/my-page`)

- 활성 세션, 내 프로젝트/워크스페이스, 자원/크레딧 이력, 알림 수신 설정 항목을 SFR-019 범위에 맞춰 보강합니다.
- 실증 프로젝트 참여 이력과 K-RMF 증빙 담당 항목을 추가합니다.
- API Key 관리는 연동 전 mock 상태로 유지하고, 실제 연동 시 Vault 연계를 전제로 합니다.

### 3.5 K-RMF 증빙관리 (`/krmf-evidence`)

- SER-002~SER-008 통제항목을 K-RMF 증빙관리 대시보드에 매핑합니다.
- 통제항목별 **이행 계획**, **증빙자료**, **미흡사항**, **타 수행사 제출자료**, **평가/인가 상태**를 탭/필터로 관리합니다.
- 운영전환 자료(인가 후 인수인계 문서)를 별도 보관함으로 추가합니다.
- 보안등급에 따른 접근 제어와 감사 이력을 기본 전제로 합니다.

### 3.6 플랫폼 API 연계현황 (`/platform-api-integration`)

- AI/데이터/클라우드/CMP 연계 후보에 SFR-007/008/018 관련 항목을 보강합니다.
- K-RMF 증빙 동기화, 감사 로그 수집, 실증 프로젝트 상태 연계 후보를 추가합니다.
- 연계 상태(`PoC Mock`, `설계필요`, `후속연동`)를 재점검하고, 최종공고문에서 명시된 전제조건을 비고에 기술합니다.

### 3.7 업무흐름/연계 시나리오 (`/workflow-scenarios`)

- AI/데이터 작업환경 신청 → 승인 → 프로비저닝 → 워크스페이스 접속 → 반출/종료 시나리오를 갱신합니다.
- 실증 프로젝트(TER-008) 시나리오: 3개 과제 등록 → 소요부대 확대 → 결과 수집/반출 → 평가보고를 추가합니다.
- K-RMF 인가 시나리오: 통제항목 식별 → 증빙 수집 → 내부 검토 → 평가/인가 → 운영전환을 추가합니다.

## 4. 미수정/후속 범위

- **소스코드 변경 없음**: 본 단계에서는 화면 컴포넌트, mock 데이터, 라우트를 수정하지 않습니다. 문서와 매핑 정리만 수행합니다.
- **실제 연동 개발**: AI/데이터 플랫폼, 클라우드/CMP, K-RMF 시스템과의 실제 API 연동은 후속 단계에서 각 플랫폼 담당 팀과 함께 진행합니다.
- **실증 모델 정확도 보장**: TER-008 실증 모델의 성능·정확도는 AI/데이터 플랫폼 및 과제 수행팀 책임이며, 포털은 진행 현황과 산출물 관리만 지원합니다.
- **보안/K-RMF 인가 결정**: SER-002~SER-008의 증빙 충족 여부와 최종 인가는 보안 담당자/평가 기관이 결정하며, 포털은 증빙 자료를 체계적으로 관리하는 도구 역할을 수행합니다.
- **인프라 엔진 구축**: Kafka, Spark, Trino, Ceph, HDFS, Vector DB, 라벨링 엔진, 비식별화 엔진 등은 포털 구현 범위에 포함되지 않습니다.
