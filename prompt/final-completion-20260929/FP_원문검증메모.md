# FP 원문 기준선 및 프롬프트 사용 안내

작성일: 2026-09-29.

## 사용 방법

Kimi Code에 다음을 전달한다.

```text
prompt/final-completion-20260929/Kimi_Code_최종기능완성_개발프롬프트.md를 읽고 실행해줘.
같은 폴더의 FP CSV·추출검증 JSON·원문검증메모와 요구사항 폴더의 PDF를 함께 참고해.
기존 작업을 보존하면서 구현과 검증을 끝까지 진행하고,
마지막에는 PDF 531개 항목을 기준으로 개발완료·미비사항을 실제 엑셀 파일로 만들어줘.
```

이번에 만든 파일은 개발 지시와 원문 기준선이다. 애플리케이션 코드는 변경하지 않았고, 이번 검토에서 제품 빌드·업무 실행시험이나 기능별 완료 판정을 수행하지 않았다. 최종 개발결과 엑셀은 Kimi Code가 실제 구현·검증 후 작성하도록 지시했다.

## 원본 및 추출 결과

- 원본: `요구사항/01. (ICTWAY) 견적서(안)_국방 지능형 플랫폼 고도화 구축사업_견적(안)_260812_v1.0.pdf`
- SHA-256: `72c6efb629cefd2100b477522058c93a1323f464cc6aded19adc2b2b2d16ab59`
- 15페이지, 531개 데이터 행. 제목·열 머리말은 제외했다.
- EI 115, EQ 200, EO 193, ILF 17, EIF 6. 거래 기능 508행과 데이터 기능 23행이다.
- K-RMF 관리지원 24행, K-RMF 관련 데이터 기능 2행으로 총 26행이다.
- 가중치 숫자 단순합: 2,403.5. 원문의 값들을 합산한 참고값이며 FP 산정 타당성이나 견적 금액을 재검증한 수치가 아니다.
- 페이지별 행 수: `35, 37, 37, 35, 37, 35, 36, 37, 37, 38, 41, 38, 26, 35, 27`.

PyMuPDF의 표 추출로 원문 셀을 읽었다. 별도로 PDF 텍스트의 FP 유형 토큰을 세어 표의 유형별 행 수와 일치함을 확인했다. CSV 재읽기, 고유 ID 531개, 필수 원문 열 비어 있음 0건, K-RMF 26행도 검사했다. 14~15페이지는 렌더링한 원문 화면을 확인했다. 전체 행의 글자 단위 수동 교정을 완료했다는 의미는 아니다.

`FP_요구사항_원문기준.csv`는 UTF-8 BOM으로 저장했다. 원문 추출 열에는 줄바꿈과 원문상의 공백을 보존했다. 정리 열은 줄바꿈·공백을 정리한 작업용 값이다. 페이지내행은 열 머리말 다음의 첫 데이터 행을 1로 센다. `FP_ID`는 이 검토에서 부여한 추적 ID이며 PDF에 인쇄된 번호가 아니다.

## 추출 확인사항

| FP_ID | 확인사항 | 처리 |
|---|---|---|
| FP-P15-005 | 사용자 계정/프로필 비고가 `SFR-002, SFR-003, SFR-`로 끝남 | 보이는 원문만 유지, 마지막 번호 확인 필요 |
| FP-P15-013 | 반입·반출 신청 비고가 `SFR-009, SFR-010, SFR-`로 끝남 | 보이는 원문만 유지, 마지막 번호 확인 필요 |
| FP-P15-024 | 클라우드/CMP 자원·사용량 비고가 `SFR-016, SFR-017, SFR-`로 끝남 | 보이는 원문만 유지, 마지막 번호 확인 필요 |
| FP-P15-006 | `외부사용자/접속기간` 마지막 글자가 다음 셀로 넘어가 추출됨 | 추출값 보존, 정리명에만 전체 업무명 복원 |
| FP-P15-007 | 앞 행의 `간`이 역할/RBAC/권한 정책 추출값에 포함됨 | 추출값 보존, 정리명에서 혼입 글자 분리 |

PDF 자체의 배치 문제와 텍스트 추출 문제를 추적할 수 있도록 원문 추출값을 남겼다. 이 항목들로 전체 개발을 중단할 필요는 없으며 보이지 않는 요구사항 번호만 임의 확정하지 않는다. 원본 편집파일이나 별도 RFP를 확보하면 정리값과 확인상태를 갱신하고 이력을 남긴다.

## 이번 요청으로 갱신한 기존 지시

- 과거 K-RMF 기능 보류 → 컴팩트한 모니터링과 필요한 등록·검토·출력 기능 구현.
- 과거 한국어 핵심 주석 작성 → 이번 단계의 신규 설명 주석 보류, 기능·시험 우선.
- 과거 문서의 완료 상태 → 현재 소스와 새 실행 증거에 따른 재판정.
- 세분화된 FP 목록 → 원문 행은 전부 보존하고 공통 구현에 연결. 메뉴·화면 수를 원문 행 수만큼 늘리지 않음.
